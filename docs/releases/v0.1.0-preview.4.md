> 这是需要手动安装和放行的阶段性预览包，没有 Apple Developer ID 签名，也未经过 Apple notarization。它不是正式 `v0.1.0`，不能保证首次双击直接打开。

## 本次修复

- 将官方 Radar 单次 HTTP 请求的默认超时从 3 秒提高到 8 秒，覆盖 `index.json` 和快照归档请求，降低官方端点短时首字节延迟造成的冷启动回退。
- App 刷新失败后的首次自动重试从 5 分钟提前到 30 秒；连续失败仍按 5 分钟、15 分钟、1 小时和 6 小时退避，避免高频请求。
- 刷新继续在后台执行并优先展示最近的有效缓存或内置快照；本次不加入 HTTP 层即时重试，也不改变第一方快照的 HTTPS 与 provenance 信任门禁。
- marketing version 保持 `0.1.0`，build number 升级为 `103`；预览打包默认 label 升级为 `preview.4`，并拒绝覆盖已经公开的 `preview.1`、`preview.2` 与 `preview.3`。

## 首次安装

1. 打开 DMG，把 `modeldial.app` 拖到 `Applications`，推出 DMG 后从 `Applications` 启动。
2. 如果 macOS 阻止首次打开，关闭提示，进入“系统设置 → 隐私与安全性”。
3. 在安全性区域找到 ModelDial 被阻止的提示，点击“仍要打开（Open Anyway）”并确认，再从 `Applications` 启动。
4. 如果没有显示“仍要打开”，重新尝试打开一次 App，再回到“隐私与安全性”查看。不同 macOS 小版本的提示文字可能略有差异。

不需要关闭 Gatekeeper。不要执行 `xattr -dr com.apple.quarantine`、`spctl --master-disable` 或其他绕过系统安全检查的命令；如果来源无法确认，请停止安装并重新核对资产和 SHA-256。

## 已知限制

- 该预览候选没有 Developer ID、secure timestamp、Apple notarization 或 stapling；即使本地构建通过，也不等于正式发行或 Gatekeeper 干净机验收。
- 冷缓存会依次请求索引和所需归档；当前 8 秒是每个请求的门限，不是整个 feed 刷新的总时间预算。刷新在后台执行且失败后保留有效回退，但全流程总预算仍是后续加固项。
- unsigned preview 不进入正式 Sparkle `appcast.xml`，不提供自动更新或 Homebrew Cask。
- 不支持 Intel Mac，Windows 客户端仍是后续独立里程碑。
